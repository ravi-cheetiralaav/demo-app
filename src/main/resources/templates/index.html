Mission briefing

Callsign Maverick is cleared for takeoff

A small Java web application with one job: prove that it is alive on Kubernetes and tell you exactly where it landed.

◎

Objective

Serve this page from a pod. Every refresh reports the pod and node that answered, so you can watch the load balancer at work.

✦

Aircraft

Spring Boot on Java 21, packaged as a slim container image that runs as a non-root user.

⌂

Airfield

GDC ag Kubernetes. Three replicas spread across nodes behind one Service, with rolling updates that never drop below full strength.

Pre-flight checklist

All systems go

  • Container image built and publishedMulti-stage build, tests run before the image is produced
  • Liveness and readiness probesTraffic only reaches pods that report ready
  • Zero-downtime rolling updatesNew pods start before old ones are retired
  • Hardened runtimeNon-root user, read-only filesystem, all capabilities dropped
  • Replicas spread across nodesOne node going down does not take the app with it
  • Resource requests and limits setPredictable scheduling and no noisy neighbours
Flight path

From source code to the cluster

  1. BuildMaven compiles and runs the automated tests
  2. ContaineriseDockerfile produces a layered, minimal image
  3. PublishImage is pushed to the registry with a version tag
  4. DeployKubernetes rolls the new version out pod by pod
  5. VerifySmoke test checks health, version and pod identity
